    API reference

    Most code needs only the three estimators. The layers beneath them are public as well, for running a search or a selector on its own, writing a scorer, or building and evaluating expressions directly.

    Estimators

    beamfeat.BeamFeatRegressor

    Bases: RegressorMixin, _BeamFeatBase

    Constructs features, then fits a linear model on them.

    The linear model is the point: its coefficients combine with the feature formulas to give a closed-form expression for the fitted relationship, available via equation().

    Parameters:

    Name Type Description Default
    alpha float | str

    Ridge regularisation strength for the downstream model. The default "auto" selects the strength by efficient leave-one-out cross-validation over a logarithmic grid, which stays stable when many correlated features are selected from few rows; pass a float to fix the strength instead.

    		 'auto'

    Other arguments match BeamFeatTransformer.

    Attributes:

    Name Type Description
    features_

    Selected expressions.
    feature_formulas_

    Their formula strings.
    model_

    The fitted downstream linear model, None when no feature was kept.
    scaler_

    The StandardScaler applied to the features before the linear model, None when no feature was kept. coef_ divided by its scale_ gives the coefficients on the raw features.
    coef_

    Coefficients of the downstream model, on the standardised features.
    intercept_

    Intercept of the downstream model; the training mean of the target when no feature was kept.
    alpha_

    The ridge penalty used, chosen by cross-validation when alpha="auto"; None when no feature was kept.
    fdr_scope_

    Which set fdr_controlled_ is a statement about; see BeamFeatTransformer. "screened set" is what equation() marks in its output.
    equations_

    The forward path through the screened set, one record per number of terms, with the record of the fitted model marked; see BeamFeatTransformer and equations().

    The other fitted attributes, such as selection_report_, are those of BeamFeatTransformer.

    equations(precision=4, max_n_terms=None)

    Return the forward path through the screened set, one equation per size.

    Line k holds the k terms the greedy forward step of parsimony="forward" would fit if it stopped there, with its complexity, the in-sample R^2 of a least-squares fit of those terms on the rows screening used, and the R^2 its last term added. The line holding the returned features is marked *; at the default settings it is the first line whose successor adds less than parsimony_tol. At the default forward step, the line where parsimony_alpha=0.05 would stop is marked a when it holds fewer terms. The records behind the text are equations_.

    Each line is written y ~ a + b: a linear model in those terms, without coefficients, since only the marked line has fitted ones, which the regressor's and classifier's equation() prints. For classification the R^2 is that of the integer-coded labels, the ranking heuristic the forward step uses, and not a classification metric.

    The FDR guarantee covers the screened set, the last line, and not an equation chosen from this list: every line is a subset of the screened set chosen on the rows screening used, as the features returned at the default settings are. The output says so in its last line.

    beamfeat.BeamFeatTransformer

    Bases: TransformerMixin, _BeamFeatBase

    Constructs and selects features, for use inside a pipeline.

    Parameters:

    Name Type Description Default
    scorer str | Scorer

    Scoring strategy for the search. A name ("correlation", "spearman", "mutual_information", "gradient_boosting", or an alias such as "mi") or a Scorer instance.

    		 'correlation'
    selector str | Selector | None

    FDR-controlled selector, or None to keep the search output unfiltered. A name ("permutation", "knockoff") or a Selector instance, whose own settings apply in place of target_fdr and selection_correction.

    		 'permutation'
    problem_type str

    "regression" or "classification". Determines how the scorer and selector treat the target.

    		 'regression'
    max_depth int

    Maximum expression depth.

    		 2
    beam_width int

    Expressions retained at each search depth.

    		 50
    max_features int | None

    Cap on the features the search ranks by score, before selection; residual_slots adds up to that many more.

    		 None
    target_fdr float

    Nominal false discovery rate for the selector.

    		 0.1
    unary_ops tuple[str, ...]

    Unary operators to apply. "sign", off by default, adds switches at zero, such as x2*sign(x0) for a target whose slope in x2 changes sign with x0.

    		 DEFAULT_UNARY
    binary_ops tuple[str, ...]

    Binary operators to apply.

    		 DEFAULT_BINARY
    redundancy_threshold float

    Absolute correlation at or above which a candidate is treated as a duplicate.

    		 0.95
    include_originals bool

    Whether input columns compete alongside constructed expressions.

    		 True
    units dict[str, Any] | None

    Optional units of the input columns: a mapping of column name to unit, or a sequence with one unit per column. A unit is a pint quantity or unit, or a string pint parses, such as "kg" or "m / s**2". Supplying units restricts the search to dimensionally valid expressions; cover every column, since one without a unit combines freely with the rest.

    		 None
    selection_holdout float | None

    Fraction of the training rows held out of the search for selection, strictly between 0 and 1, or None to select on the search rows (which forfeits the guarantee, so fdr_controlled_ is then False).

    		 0.5
    parsimony_holdout float | None

    Fraction of the selection rows held back to re-test the returned terms, strictly between 0 and 1, or None (default) for no re-test. certify_test sets the test.

    		 None
    selection_correction str

    "by" (Benjamini-Yekutieli, default) or "bh" (Benjamini-Hochberg), used when selector is the name "permutation". A selector instance keeps its own correction and target_fdr, and a warning names any estimator setting it overrides; PermutationSelector() defaults to "bh".

    		 'by'
    on_no_discoveries str

    What to return when the screen rejects no null: "empty" (default) keeps no constructed features, "fallback" keeps the unfiltered search output with fdr_controlled_ False, "raise" raises NoDiscoveriesError.

    		 'empty'
    parsimony str | None

    "forward" (default) fits a compact subset of the screened set, chosen by greedy forward selection on the selection rows. That subset is not re-tested, so the FDR guarantee covers the set it was drawn from and not the terms returned, and fdr_scope_ (and the regressor's and classifier's equation()) marks this whenever terms were dropped. None returns the screened set entire, so the returned features are exactly the set the guarantee covers; parsimony_holdout buys both, for rows. Either way equations_ records the forward path through the whole screened set.

    		 'forward'
    parsimony_tol float

    Minimum incremental R^2 a feature must add to be kept by parsimony="forward". Ignored when parsimony is None.

    		 0.001
    random_state int | None

    Seed. Fitting is deterministic given this.

    		 0
    verbose int

    Progress reporting to stdout. 0 (default) is silent; 1 prints one line per stage -- the split, the search, the screening, the parsimony step and the fitted result; 2 adds per-depth search detail and the strongest certified candidates with their p- and q-values.

    		 0
    n_jobs int | None

    Workers that evaluate and score the search's candidates: threads, or processes for "gradient_boosting" (see BeamSearch). 1 (default) uses the calling thread only, -1 every core, and None follows an enclosing joblib configuration (joblib.parallel_config, or parallel_backend before joblib 1.3). Small searches run in the calling thread regardless. With input_test, as many threads share its tests. The fitted result is the same for every value.

    		 1
    max_inputs int | None

    Most distinct input columns one feature may use, or None (default) for no limit. Candidates over it are ruled out during the search, before evaluation. A feature of depth d uses at most 2**d columns, so at the default max_depth of 2 a value of 4 or more has no effect. A law that needs more inputs than the limit cannot be found.

    		 None
    fitted_ops tuple[str, ...]

    Parametric operators whose one constant is fitted inside the expression: "exp_scaled" (exp(a*x)), "pow" (x^a), "inv_shift" (1/(x + a)) and "log_shift" (log(x + a)). All four by default; () keeps every expression free of constants, as the default did before 0.6.0, and fits about twice as fast on small data. "sign_shift" (sign(x + a), its threshold between the operand's 5% and 95% quantiles) is off by default; it adds switches away from zero, such as x2*sign(x0 - 0.7). The constants are fitted during the search, on the search rows only (see BeamSearch), so the screen on the selection rows sees fixed expressions and its guarantee is unchanged; with selection_holdout=None the rows are shared, as they are for the search itself. A fitted constant is part of the expression: transform and predict reuse it, and the formulas and to_sympy() show it, as an exact fraction when it was snapped to one. A law the plain operators can write keeps its plain form unless the snapping test, on the search rows, rejects the null that the plain form fits as well: log(x0), not a fitted near copy such as (x0)^(-0.02).

    		 DEFAULT_FITTED
    certify_test str

    The test the parsimony_holdout re-test applies to each returned term on the held-back rows. "marginal" (default) re-runs the configured selector, whose null is that the term is independent of the target, so it rejects the null of a term that only rides on a true one, x0*x7 when the target depends on x0 alone. "conditional" tests each term given the other returned terms, with a Freedman-Lane permutation test: the target and the term are residualised on the other terms and an intercept, the target's residuals are permuted, the statistic is the partial correlation, and the screen's step-up correction is applied at the screen's level. Its null is that the term's coefficient is zero in a linear model of the target on all the returned terms. A term standing in for a true one the others leave out is not null in that sense, so rejecting its null is not a false rejection. Its p-values are approximate: they rest on the errors of a linear model of the target on the other terms being exchangeable (independent and identically distributed, say, so of constant variance), and are close to exact rather than exact even then, except for a single term, where the test is the marginal one. If the re-test rejects no null, the screened set is returned, which carries the screen's marginal guarantee only. After the forward step "conditional" needs parsimony_alpha: without it the step hands the re-test riders it cannot certify, and on noisy data the screened set comes back in most fits, so that combination raises. With parsimony=None the re-test sees the whole screened set and needs no parsimony_alpha. Regression only; ignored when parsimony_holdout is None. See the guarantees page for its measured calibration.

    		 'marginal'
    magnitude_slots int | str

    Beam slots added at each search depth for candidates ranked by how well their magnitude tracks the target's, for laws whose parts do not correlate with the target, such as x0*x1*x2 with centred inputs, whose pairwise products the score's ranking leaves among noise. "auto" (default) adds 10 for regression and none for classification, whose labels carry no magnitude; 0 adds none, the default before 0.7.0. On wide tables, where the first depth cannot propose every pair of inputs, the inputs are also proposed in an order that interleaves the two rankings. The ranking is part of the search, on the search rows only (see BeamSearch), so the screen on the selection rows sees fixed expressions and its guarantee is unchanged. A positive value is for regression only.

The null is that the column is independent of the target and of the candidate's other columns, under which the p-values are exact: it removes (x0*x1)/(x1 + x8) when x8 is unrelated to everything, but a junk column correlated with a real one is not null in that sense, so its null can be rejected and the term kept.     Screening another tool's equation

    beamfeat.screen

    Screen another tool's equation on rows it did not see.

    A symbolic regression tool (PySR, Operon, gplearn, PySINDy and the like) reports an equation fitted on some rows, with no statement about whether its terms are real. screen_equation() tests the equation's terms on other rows, which the tool never saw. There the terms are fixed functions, so a permutation test of each term against the target is valid in finite samples, whatever the tool did to find them.

    The marginal test. Each top-level additive term of the equation, as written, is one candidate. Its null is that the term is independent of the target. The test is the one beamfeat's own fits use, PermutationSelector: the term's absolute Pearson correlation with the target against the same statistic on permuted targets, with the add-one p-value. The Benjamini-Yekutieli step-up (correction="by", the default) controls the false discovery rate among the kept terms under any dependence between their p-values; Benjamini-Hochberg ("bh") needs positive dependence.

    The input test (input_test=True). The marginal test keeps a term such as x0*x7 when x0 carries it, whatever x7 is. The input test asks, of each variable of each term that uses more than one, whether the term needs it: the variable's rows are permuted inside the term alone and the term's correlation with the target is recomputed, every pair against the same permutations. A variable's null is that it is independent of the target and of the term's other variables together. The p-value is the add-one estimator over the fewest draws that let the strictest step-up threshold be reached (at least 1,000), except that a pair stops at its tenth exceedance, after L draws, with p = 10 / L (Besag and Clifford's sequential estimator, valid in the same sense). The step-up runs over every (term, variable) pair of every term, kept by the marginal test or not, so which pairs are tested does not depend on the marginal outcome. A term is kept when the marginal test rejects its null and, with the input test, the input test rejects the null of each of its variables. A variable correlated with another input is not null in this sense, so a stand-in for a true input can have its null rejected: no test of association can tell the two apart.

    What is never kept. A term undefined (not finite, or not real) or constant on any of the rows cannot be tested. It is reported as untestable and never kept, and so is every pair of it in the input test.

    Coefficients. The kept terms are reported as the tool wrote them. To use them, refit their coefficients on the rows the tool searched, never on the rows that screened them: a refit on the screen rows would reuse them.

    Few rows make a weak test. A term the screen does not keep has no support on these rows, which is not a finding that it is false. With a few dozen rows a real term of modest effect is often not kept.

    Stability over splits

    beamfeat.stability

    How much a fitted equation depends on the split it was fitted on.

    A fit prints one equation, found on one random split of its training rows into a search part and a selection part. Where many expressions predict about equally well, another split, or another sample of rows, prints another equation, and nothing in a single fit shows whether the printed one is the discovery or one draw among many equally good ones. stability_report() measures it, as the stability study of the beamfeat paper (TMLR 2026, Appendix E) did, by refitting on many random splits and counting the distinct equations they print.

    Splits. Each of n_splits splits divides the rows at random into a training part and a test part of test_size (stratified by class when the estimator classifies). A clone of the estimator, with a random_state of its own, is fitted on the training part: the search, the screen, the parsimony step and the downstream model never see the test rows. The clone is then scored once on the test part. The partitions and the clones' seeds come from a numpy.random.SeedSequence of random_state, one child per split, so a report is the same on every run with the same random_state, whatever n_jobs is, and the first k splits are the same whatever n_splits is.

    What varies. By default (resample="splits") each split draws its own partition as well as its own seed. The report then measures split-to-split variability: how far the equation and the score move with another sample of training rows, another test part and another seed, and the spread of the scores includes the variation between test parts. With resample="seeds" every split keeps the partition of the first, and only the clones' seeds differ, as in the paper's study. That measures seed-to-seed variability on fixed data: how far the equation moves with the random search/selection split inside the fit alone, which is the split the guarantee is conditional on, and the scores vary only through it.

    Equivalence. Formulas spelled differently can be the same feature: log((x0 * x1)) and (log(x0) + log(x1)), or (x0 - x1) and (x1 - x0). Every selected feature is evaluated on the rows of X, or on 1500 of them drawn at random when there are more, and the target is not used. A feature belongs to the first class, in order of appearance, whose first member it correlates with above 0.999 in absolute value, on at least 50 rows (or on every row, when there are fewer) where both are defined. This is the value-equivalence of the paper's study. It merges rewritings, and rescalings, shifts and sign flips, which a linear model's coefficient and intercept absorb. It also merges near-duplicates whose values agree that closely on the data, such as one expression on two almost identical columns. Identical formulas are always one class, and a feature that cannot be compared, being defined on too few rows or constant on them, shares its class only with identical formulas. An equation is the set of the classes of its features: two splits print the same equation when their features fall in the same classes, whatever the coefficients.

    Search

    beamfeat.search

    Target-guided beam search over the expression DAG.

    Exhaustive expansion is the scaling failure of breadth-first feature construction: the candidate count compounds at every depth, and the cost is paid in full before any of it is scored. This module instead expands only a bounded frontier. At each depth, every surviving expression is extended by the available operators, the resulting candidates are scored against the target, and only the best beam_width survive to be extended again.

    Two properties keep the beam useful rather than merely small:

    Marginal scoring. Once features have been selected, each candidate is scored both against the raw target and against the residual left by the selected features, and ranked on the larger of the two. The residual score rewards a candidate that explains something new; the raw score keeps alive a refinement of an incumbent, such as log(a) when a is already selected, which the residual alone would discard.

    Redundancy pruning. Ranking on the larger score lets a beam fill with mutually correlated variants of one expression. Before a candidate is admitted to a depth's beam, its correlation against everything already admitted at that depth is checked, and it is dropped if it reaches redundancy_threshold. The check is within a depth: a candidate that restates a feature from an earlier depth can occupy a beam slot. Such restatements are removed in the final ranking, which applies the same check across all depths.

    Magnitude slots (magnitude_slots), off by default here and on by default in the estimators for regression. A part of a law can be uncorrelated with the target, as x0*x1 is with x0*x1*x2 when the inputs are centred, and the score then ranks it among noise. With the option, each depth but the last keeps a few more candidates, those whose magnitude best tracks the target's (see magnitude_scores()), and a first depth too wide to propose every pair proposes those inputs early.

    Residual slots (residual_slots), off by default. The final ranking keeps the max_features candidates that score best against the target, and a dominant term fills it with restatements of itself, so that a weaker term beside it, such as log(x3) in x0*x1/x2 + 0.5*log(x3), is cut although the search built it. With the option, the first terms of a greedy forward path through every candidate the search kept join the ranking, each the one that adds most to a least-squares fit of those before it; a restatement adds nothing to the term it restates, and the weaker term comes second. The path also chooses among the transforms of a path term's operand, which a depth may have dropped as near copies of one another.

    Memory stays bounded as well. On a wide table one depth can propose hundreds of thousands of candidates. They are evaluated and scored a chunk at a time (chunk_size, by default as many columns as fit in CHUNK_BYTES) and only their scores are kept; the candidates the redundancy pass reaches are evaluated again. Peak memory then depends on the chunk and the beam rather than on the number of candidates. A scorer whose scores depend on the whole batch, such as mutual information, still receives a depth at once.

    Search is deterministic: given the same data, parameters, and random_state, the returned features and their order are identical across runs, whatever n_jobs and chunk_size are set to.

    beamfeat.parametric

    Fitting the constant of a parametric operator.

    A parametric operator, such as exp_scaled (exp(a*x)) or inv_shift (1/(x + a)), carries one constant. fit_constants() chooses it for a given operand by a one-dimensional search: a coarse grid from the operator's constant_grid, then a golden-section refinement between the grid neighbours of the best point. fit_constants_many() fits many operands at once: the refinements and the snapping run side by side, one array operation per step for all of them, which is what a search fitting hundreds of operands needs.

    Objective. The constant maximises the absolute Pearson correlation of the transformed operand with the target, whatever scorer the search uses. Correlation is smooth in the constant and costs one pass over the rows, so the fit stays cheap for any scorer; the configured scorer then ranks the fitted node against every other candidate. Correlation is also what the final linear model rewards: a feature with correlation r leaves a fraction 1 - r^2 of the target's variance unexplained on its own.

    A constant is often only identifiable in context: 1/(x0*x1 + a) is the denominator of (x0 + x1)/(1 + x0*x1), and alone it correlates best with the target as a approaches the pole. When the caller passes partners (expressions the result may be multiplied by), the fit is therefore also run on the product with each, and the constant best for the best partner is returned beside the one best alone. BeamSearch proposes the node with each constant, and the product with its partner, as candidates to be scored like any other.

    Discarded fits. A fit whose best grid point is the end of a grid segment ran into a bound -- the margin a shift keeps between its pole and the data (see pole_margins()), the smallest positive power when the operand comes within that margin of 0 (the pole of a negative power), the linear limit of a small scale, the step limit of a large one, or the outermost quantile a threshold of sign_shift may take -- and is discarded, as is one whose values are not finite, constant, or outside the operator's domain. Snapping and rounding stay within the same bounds, so a simple constant never moves a pole closer to the data than the margin. And since every operator but sign_shift tends to an affine function of its operand at one end of its range (a small scale, a distant shift, a power of 1), a fit is also discarded unless the likelihood-ratio test below rejects the null that the operand itself, or for a product the partner alone, fits as well; otherwise the constant only fits noise. A threshold of sign_shift is held to the same test.

    Snapping. The data rarely pin a constant to more digits than they support, and exp(-0.49991*x^2) is a worse answer than exp(-x^2/2). After the refinement, the simple values of SNAP_VALUES (0, +-1, +-2, +-3, +-1/2, +-3/2, +-1/3, +-1/4) are tried. For each, a likelihood-ratio test asks whether the data reject the null that the constant takes that value, and the simplest value it fails to reject is used: the smallest denominator, then the best fit. The test is for a least-squares fit of the target on the feature: with L(a) = 1 - r(a)^2 the unexplained fraction and n the rows, it fails to reject when n * log(L(simple) / L(optimum)) is at most SNAP_LR, the 99.9% point of a chi-squared variable with one degree of freedom, so it runs at level 0.001. A tolerance stated this way scales with the noise and the sample: on near-noiseless data the test fails to reject only a value that fits essentially as well as the optimum, on noisy data a wider range, as it should. A fixed tolerance on |r| cannot do both; at 0.1% noise, r is within 1e-6 of 1 and a tolerance of 1e-4 would snap to a constant that leaves a hundred times the noise unexplained. The 99.9% point rather than the 95% one makes the simpler constant the default: the null for a law's true constant is falsely rejected, a Type I error, in one fit in a thousand rather than one in twenty. If the test rejects every simple value, the constant is rounded to the fewest significant digits (up to six) that cost at most ROUND_LR, so that the printed constant is the stored one.

    Everything here is deterministic.

    Scoring

    beamfeat.scoring

    Candidate scoring strategies for guided beam search.

    A Scorer answers one question: how useful is this candidate feature, given the target and the features already selected? The "given the features already selected" part is what keeps a beam from filling with near-duplicates of the same underlying signal, which is the dominant failure mode of scoring candidates in isolation.

    Four strategies are provided, trading signal quality against cost:

    CorrelationScorer Absolute Pearson correlation against the residual left by the incumbent features. Cheapest by a wide margin; detects only monotone-linear relationships to the residual, but that is often enough to find a feature whose nonlinearity is already baked into its expression.

    SpearmanScorer Absolute rank correlation against the same residual. One sort per column dearer than Pearson; sees any monotone relationship and is insensitive to outlying values.

    MutualInformationScorer Nearest-neighbour mutual information between candidate and residual. Detects nonmonotone dependence that correlation misses, at roughly one to two orders of magnitude more compute.

    GradientBoostingScorer Measured out-of-fold improvement in predictive performance when the candidate is added to the incumbent set. The most faithful signal, since it scores what is actually being optimised, and the most expensive.

    All scorers are deterministic given a random_state, and all handle the empty-incumbent case (the first beam round, where there is no residual yet) by scoring against the raw target.

    A scorer whose score for a candidate depends on that candidate's column alone declares itself separable. A round can then be scored in pieces: prepare() handles the target and the incumbents once, and score_prepared() scores any chunk of candidates against the result, reusing the ColumnStats computed when the chunk was evaluated. The scores equal those of score_batch() on the whole round, which is how the search keeps its memory bounded.

    Out-of-fold predictive improvement from adding the candidate.

    SpearmanScorer

    Bases: CorrelationScorer

    Rank correlation: Pearson on the rank-transformed candidate and target.

    Invariant to monotone transforms of either variable and insensitive to outliers in the tails, so it is the natural choice when the relationship is monotone but nonlinear, or when heavy-tailed values would let a few extreme rows dominate a product-moment correlation. It shares the structural limits of any single-column score: a non-monotone relationship (a symmetric bump) and a marginally-quiet-but-jointly-essential feature are both invisible to it, exactly as to Pearson.

    Residualisation follows CorrelationScorer; ranks are taken after residualising, so the score measures monotone association with what the incumbent set has not explained. Tied values share their average rank, so a score never depends on row order; a constant candidate, or an incumbent set that explains the target exactly, scores zero, and a candidate with a non-finite value scores zero, as under CorrelationScorer.

    For classification only the candidates are ranked. A classification residual is a label minus a fitted function of the incumbents, so within each class its order is set by the incumbents alone; ranking it would turn that order into signal, and a copy of an incumbent would score well. Without incumbents the two coincide, since the ranks of a binary residual are an affine function of it.

    Leverage caveat: rank transformation hides magnitudes, so a feature with a near-singularity (a reciprocal or logarithm evaluated close to its pole) can rank-correlate well while carrying extreme values that destabilise the downstream least-squares fit. The estimators' holdout fit check (DegenerateFitWarning) flags the resulting failures; treat that warning seriously when this scorer is selected.

    column_stats(values)

    Mean, variance and magnitude of every column of a 2-D array.

    Each column is reduced as a contiguous vector, so every statistic equals the one computed from that column on its own, to the last bit; reducing along the rows of a row-major matrix sums in a different order. Overflow is not reported: it shows up as an infinite variance.

    is_constant(values)

    Whether a column carries no variation a scorer can use.

    Constancy is judged relative to the values' magnitude rather than by an absolute floor on the spread, since an absolute floor makes the verdict depend on the column's units: a product of small-unit columns sits at the product of their magnitudes and lands under any fixed floor while carrying real signal. A spread twelve orders below the magnitude is far inside accumulated float64 rounding noise, so nothing informative is discarded.

    Exposed so that a caller screening a wide table can apply the same test the estimator applies, and so that the diagnostic reported at fit time cannot drift from the behaviour it describes.

    Selection

    beamfeat.selection

    False-discovery-rate controlled feature selection.

    Feature construction proposes far more candidates than any dataset can support. Each candidate carries its own null hypothesis, and the selected features are those whose nulls a selector rejects. This module provides selectors that control the false discovery rate — the expected proportion of rejected nulls that are true, that is, of selected features that are spurious — and is explicit about the assumptions under which each guarantee holds.

    PermutationSelector (default) A permutation test of marginal association, corrected for multiplicity. The test statistic is a fixed function of the data (|Pearson correlation| for regression, eta-squared for classification), so permuting the target yields p-values valid in finite samples for the null hypothesis that a feature is marginally independent of the target (Phipson & Smyth, 2010). Multiplicity is handled by Benjamini-Hochberg, valid under positive regression dependence, or Benjamini-Yekutieli, valid under arbitrary dependence (Benjamini & Yekutieli, 2001). This class defaults to the former; the estimators default to the latter, since engineered candidates share parents and positive dependence cannot be assumed.

    The marginal null composes correctly with constructed features: two
near-duplicate expressions of one true signal are *both* genuinely
associated with the target, so selecting both is not a false discovery
under this null. De-duplication is the job of the redundancy pass, not
the error-control procedure.

    KnockoffSelector The knockoff filter. Two constructions are provided and routed automatically:

    - **Fixed-X** (Barber & Candès, 2015), used when ``n > 2p``. Treats the
  design as fixed and makes *no distributional assumption about the
  features* — deterministic engineered columns are fine. The guarantee
  requires the linear model ``y = X beta + noise`` with Gaussian,
  homoskedastic noise, and a design of full column rank, and a statistic
  that sees the data only through ``[X X~]' [X X~]`` and ``[X X~]' y``;
  the lasso-path entry statistic used here is one. Columns that
  are constant or linearly dependent on earlier ones are left out of the
  construction and cannot be selected (see `KnockoffSelector`).
- **Model-X Gaussian** (Candès et al., 2018), used when ``n <= 2p``, or
  on request. Requires the features to be jointly Gaussian, which
  engineered features are not, so a warning is recorded whenever it
  runs.

    The estimators' certify_test="conditional" re-tests the terms they return with a Freedman-Lane permutation test of each term given the others. It is not a screen and is not exported; its null and the assumptions behind it are stated with that parameter and on the guarantees page. The estimators' input_test=True tests, for each column a candidate reads, the null that the column is independent of the target and of the candidate's other columns, by permuting that column alone; it is not exported either.

    Selective inference caveat. Every guarantee above is for testing a candidate set that is fixed before seeing the data used for testing. If candidates were chosen by a search on the same data — chosen, in part, because they correlate with this sample's target — the p-values are optimistically biased and the nominal FDR is not guaranteed. The estimators in beamfeat.estimators therefore hold out a split of the training data for selection by default; see selection_holdout.

    KnockoffSelector

    Bases: Selector

    Knockoff filter with automatic fixed-X / model-X routing.

    Fixed-X (Barber & Candès, 2015) is used when n > 2p. The design is treated as fixed, so no assumption about the distribution of the features is required — deterministic engineered columns are admissible. The finite-sample FDR guarantee (with offset=1) requires the linear model y = X beta + eps with i.i.d. Gaussian noise, and a design of full column rank.

    Statistic. On the fixed-X path for regression, the signed maximum of the lasso path: W_j = max(Z_j, Z~_j) * sign(Z_j - Z~_j), where Z_j is the penalty at which column j first enters the path. It depends on the data only through the Gram matrix of originals and knockoffs and their inner products with the target, as the fixed-X guarantee requires. Elsewhere — model-X, where any statistic that swaps sign with the pair is valid, and the heuristic classification path — it is the difference of cross-validated lasso (or L1-logistic) coefficient magnitudes. Versions up to 0.5.0 used that difference on the fixed-X path too, where cross-validation looks at individual rows and the guarantee did not strictly cover it.

    How far each knockoff is from its original. Both constructions set the correlation of column j with its knockoff to 1 - s_j; the larger s_j, the easier the lasso tells them apart. s_method chooses s. "equicorrelated" (default) uses one value, s_j = min(1, 2 lambda_min), so a single tight pair of columns shrinks s for every column. "ci" (conditional independence; Liu & Rigollet, 2019) uses s_j = c / (Sigma^-1)_jj, i.e. c times the share of column j that the other columns do not explain, with the largest c <= 1 the construction allows. Constructed candidates come in groups of near-copies (x, x^2, log x), and there "ci" keeps s large for the columns outside the tightest group. Ke et al. (2024) found it more powerful than equicorrelated knockoffs on block and factor designs; in benchmarks/knockoff_s_method.py the gain was on constructed columns, while Gaussian block and factor designs came out about equal. Both satisfy the exchangeability identities, so the guarantee is the same.

    Rank-deficient designs. When the design covariance has an eigenvalue below 1e-6 — a constant column, a duplicate, or a column that is a linear combination of others, all common among constructed candidates — every valid knockoff of the columns involved equals the column itself, and the equicorrelated s makes every knockoff nearly equal its original. The lasso statistic is then decided by its tie-breaking between identical columns, which favours the originals, so knockoff+ selects nulls. The model-X construction fails the same way. Columns are therefore dropped, latest first, until the remaining covariance is well conditioned; the dropped columns get the statistic W = 0, so they cannot be selected, and the warning lists them. The guarantee then covers the retained columns, and the fixed-X / model-X routing uses their count.

    Model-X Gaussian (Candès et al., 2018) is used when n <= 2p, where the fixed-X construction does not exist, or when construction is "gaussian". It requires the features to be jointly Gaussian, an assumption engineered features violate, and a warning is recorded whenever it runs. Prefer PermutationSelector in that regime.

    Power and the offset. offset=1 requires (1 + #negatives)/#positives <= target_fdr, unsatisfiable with fewer than 1/target_fdr features regardless of signal; measured on a 25-feature Gaussian design at level 0.1, offset=1 recovered almost nothing while offset=0 recovered everything. offset=1 remains the default because it is the stated finite-sample guarantee; a warning fires when the design is too narrow for it.

    PermutationSelector

    Bases: Selector

    Permutation test of marginal association, with FDR correction.

    Statistic. For regression, the absolute Pearson correlation between each feature and the target; for classification, eta-squared (the between-class share of each feature's variance). Both are fixed functions of (X_j, y), which is the condition for a permutation test to be valid: comparing the observed statistic to the same statistic computed on (X_j, pi(y)) over random permutations pi yields a valid p-value for the null that X_j is marginally independent of y, via the add-one estimator (1 + #exceedances) / (B + 1) (Phipson & Smyth, 2010). Statistics that re-tune themselves on the observed target — a cross-validated lasso penalty, for instance — do not satisfy this condition unless the tuning is repeated inside every permutation.

    What the null means for constructed features. Marginal independence is the appropriate null here: an expression that genuinely co-varies with the target is a true discovery even if another selected expression carries the same information. Redundancy among true discoveries is resolved by the redundancy pass in the search, not by the error-control procedure.

    Multiplicity. Benjamini-Hochberg by default, which controls FDR under positive regression dependence; set correction="by" for the Benjamini-Yekutieli procedure, valid under arbitrary dependence at the cost of a log(m)-factor in power.

    Resolution. The smallest attainable p-value is 1/(B + 1), and the leading feature has to reach the threshold its correction sets: target_fdr / m under Benjamini-Hochberg, and target_fdr / (m c(m)) under Benjamini-Yekutieli, where c(m) = sum_{j<=m} 1/j. B therefore must be at least m / target_fdr - 1 in the first case and c(m) times that in the second for the null of a lone leading feature to be rejectable at all, and one further null exceedance doubles the requirement. When auto_permutations is on (default), B is raised to twice the bound belonging to the configured correction — satisfiable with headroom for a single exceedance — capped at max_permutations. The requirement binds hardest when few candidates reach the floor together: several tied true signals relax the threshold by their count, whereas a single one carries it alone. Because the statistic is a chunked matrix product, the larger counts remain inexpensive; raising B ninefold on a 4088-column problem left the fit time unchanged within noise.

    Expressions

    beamfeat.expression

    Expression DAG with structural hashing, lazy evaluation, and unit propagation.

    The central abstraction is Node, an immutable description of how to compute a feature from input columns. Nodes are descriptions, not data: they carry no arrays. Evaluation happens on demand via Evaluator, which caches intermediate results keyed by structural hash so that shared subexpressions are computed once.

    Two design decisions distinguish this from eager approaches:

    1. Structural hashing. Two nodes describing the same computation compare equal and hash identically, regardless of construction order. This makes deduplication automatic and lets the evaluator cache across a whole search.

    2. Fail-fast unit checking. When dimensional metadata is supplied, unit compatibility is validated at construction time, before any array work. Invalid combinations raise UnitError immediately.

    Numerical failures during evaluation are never silent. Nodes that overflow, produce non-finite values, or degenerate to near-zero variance are recorded in an EvaluationLog with a reason, and excluded from results. The log is part of the public API so users can audit what was rejected.

    Many nodes can also be evaluated away from the evaluator, in another thread or process: Evaluator.plan_batch() gathers what they need into an EvaluationBatch, EvaluationBatch.run() computes them with the same checks as Evaluator.evaluate(), and Evaluator.commit_batch() records its rejections in the log.

Called with the operand's values, it returns the coarse grid of constants the fit starts from, as one or more increasing segments; a fit whose best grid point is a segment's end is rejected as running into a bound. Parametric operators must be unary, and are applied through transform() with const.

    UnitRegistryError

    Bases: UnitError

    Raised when operands carry units from different pint registries.

    pint cannot multiply or divide quantities from two UnitRegistry instances, so this is a configuration problem rather than a dimensional verdict on one candidate. Evaluator converts the units it is given into a single registry, so it only arises for nodes built directly with leaf() from mixed registries.

    pole_margins(x)

    Smallest distances a fitted pole keeps below and above the values x.

    Each is the larger of POLE_MARGIN_SPREADS times the spread of the POLE_MARGIN_ROWS most extreme values at that end (all of them, for fewer rows) and POLE_MARGIN_FLOOR times the range of x.

    The shifts of inv_shift and log_shift place their pole at least this far from the values. pow has its pole at 0 when its exponent is negative, so a negative exponent is fitted only when the smallest value exceeds the margin below; otherwise only exponents from 0.1 to 4 are.

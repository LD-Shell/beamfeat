    beamfeat

    beamfeat builds readable formulas from the columns of a table, such as (x0 / x2) * x1 or log(a) * log(b), tests each against the null hypothesis that it is independent of the target, and keeps only those whose null is rejected, with a stated false-discovery-rate guarantee. The result is a short equation in your own column names, from a scikit-learn estimator you can fit, inspect and predict with. The method is described in a TMLR 2026 paper.

    New in 0.8.0

    • screen_equation tests the equation another tool reports (PySR, Operon, gplearn, PySINDy and the like) term by term, on rows the tool never saw.
    • sign_shift, a fitted sign(x + a), finds targets that switch at a threshold, such as x2*sign(x0 - 0.7): R² 0.997 to 0.999, where the default reaches 0.76 to 0.88 and gradient-boosted trees 0.983 to 0.996.
    • residual_slots=10, beside parsimony_alpha=0.05, finds a weak term next to a dominant one: it printed x0*x1/x2 + 0.5*log(x3) exactly in 33 of 60 fits, where the default never printed log(x3).
    • max_search_rows runs the search on a sample of the rows: on 200,000 rows, a search on 10,000 of them cut the median fit from 110 to 33 seconds.

    The three options are off by default. At the defaults every fit is 0.7.0's, at the same speed and memory, on all 1,430 items of the release comparison, which measures each option against the default. Choosing a setting says when each one helps.

    An example: fat content from a spectrum

    In the tecator data, the task is to predict the fat content of meat samples from 100 near-infrared absorbance channels. Over five random 75/25 splits, beamfeat's equation uses three or four formulas, mostly ratios of channel differences such as ((x35 - x42) / (x37 - x39)), and reaches a mean held-out R² of 0.991 in the paper (0.990 with the current release). On all 100 channels, ridge regression reaches 0.957, a random forest 0.717 and LightGBM 0.756. A random forest given the formulas in place of the raw channels goes from 0.739 to 0.992, on three of the five splits. Against the methods of chemometrics, compared since the paper, the current release's error is 46 to 62% of that of partial least squares (R² 0.951 to 0.971), and the error of kernel methods on second-derivative spectra (R² 0.996 to 0.998) is 46 to 59% of beamfeat's, from every channel and with no formula to read.

    The accuracy is stable from split to split; which ratios are picked is not. Neighbouring channels correlate at 0.99988, so many ratios are nearly interchangeable, and each split settles on its own. stability_report measures this on any data: it refits on many random splits and counts the distinct equations.

    The numbers are the paper's (Table 6 and its appendices), from the archived run in benchmarks/additional_experiments/, except the chemometrics comparison, from benchmarks/tecator_chemometrics/; benchmarks/figures/tecator.py draws the plot. The Benchmarks page has all nine datasets of that study, including those where beamfeat trails.

    Install

    pip install beamfeat              # core: numpy, scikit-learn, joblib
pip install "beamfeat[units]"     # + pint, for units
pip install "beamfeat[display]"   # + sympy, for to_sympy() and latex()
pip install "beamfeat[all]"       # + both, pandas and the test dependencies

    Python 3.10 or newer, with no upper version pins: the 1,079 tests pass on Python 3.10 to 3.15 with the newest releases each supports, and the suite runs on the oldest supported stack too. Installation lists the versions, and how to run the tests or reproduce the benchmarks.

    It fits like any scikit-learn estimator:

    from beamfeat import BeamFeatRegressor

model = BeamFeatRegressor().fit(X, y)

model.formulas()        # ['((x0 / x2) * x1)', ...]
model.equation()        # 'y = 0.9847*((x0 / x2) * x1) + ...'
model.fdr_controlled_   # True: the features carry the stated FDR guarantee
model.predict(X_new)

    Three settings

    BeamFeatRegressor()                        # the equation that predicts best
BeamFeatRegressor(parsimony_alpha=0.05)    # a short equation, to read or report
BeamFeatRegressor(input_test=True)         # every column inside each formula tested

    On noisy data the default's equation can carry extra terms. On y = x0/x1 among ten unrelated columns, with noise as large as the signal, it printed a median of 9.5 terms, most of them reading an unrelated column, and parsimony_alpha=0.05 printed the one true term in every fit. On real data, which rarely follow one compact formula, parsimony_alpha gives up some held-out score, and input_test takes 2 to 7 times as long. Choosing a setting has the measurements.

    What you get

    • Readable formulas. formulas() lists the features, and equation() prints the fitted model in your column names.
    • The equation at every size. equations() lists one equation per number of terms, with the R² each term adds.
    • LaTeX and SymPy. latex() typesets the equation, and to_sympy() hands the features to SymPy, and from there to NumPy, JAX or PyTorch.
    • Units. Give the columns units, as strings such as "kg" or as pint quantities, and dimensionally invalid expressions are never built.
    • A guarantee code can check. fdr_controlled_ says whether the features carry the guarantee, and fdr_scope_ whether it covers the printed equation or the larger certified set the equation was drawn from.
    • Fitted constants. Expressions can carry one constant fitted inside them, such as exp(a*x) and 1/(x + a), which recovers laws like exp(-x^2/2) exactly. On by default; fitted_ops=() turns it off.
    • Hidden building blocks. magnitude_slots keeps a few beam places for parts whose size tracks the target's even when they do not correlate with it, such as x0 and x1 in y = x0*x1 with centred inputs. On by default for regression; magnitude_slots=0 turns it off.
    • Every column in a formula tested, opt in. input_test=True tests each column inside each formula, and drops a formula when the test fails to reject the null for one of its columns, such as x6 in (x0 * x1) / (x0 + x6).
    • Stability. stability_report refits on many splits and shows whether the equation is the only good one or one of many.
    • Another tool's equation, screened. screen_equation tests the equation PySR, Operon, gplearn or PySINDy reports, term by term, on rows the tool never saw, and keeps the terms whose null is rejected, with the same guarantee.
    • A warning beyond the training data. predict and transform warn when a new row takes a feature far beyond its range on the training rows, and the search rules out quotients whose denominator comes close to zero there.

    The guarantee

    The search runs on half of the training rows. On the other half, each formula it returns is tested against the null hypothesis that it is independent of the target, with a permutation test and the Benjamini–Yekutieli correction. The formulas whose nulls are rejected are the certified set, and on average at most 10% of them are false discoveries (target_fdr). That is an average over repeated fits, not a promise about any one fit, and it covers the certified set, of which the printed equation is by default a compact subset. A formula is a false discovery only when it is independent of the target, so (x0*x1)/(x1 + x8) is a true one when y = x0*x1, however unrelated x8 is; input_test=True tests each column inside each formula. If no null is rejected, the model uses no formulas and warns. Statistical guarantees gives each procedure's assumptions and what was measured.

    The Zenodo DOIs archive the code, not the paper: 10.5281/zenodo.23417132 is 0.4.2, the version the paper describes, with the run records behind its results, and 10.5281/zenodo.21619567 collects every release. CITATION.cff has the same details in machine-readable form.

    Later releases correct two of the paper's results, detailed on the Benchmarks page: a harness bug understated featuretools, and fixing a search bug takes the datasets where beamfeat leads both tree ensembles from five to four.

    Please also cite the statistical methods behind the options you use: Citing beamfeat lists which work goes with which option, with BibTeX.
